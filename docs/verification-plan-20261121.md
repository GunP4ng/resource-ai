headlines. The six-stage view uses Korean route names and formatted cost/carbon

## Model-selected verification order

The existing assessment tool now supplies host-issued candidate checks derived
only from current questions, reasons and pre-execution checks. Internal answer
syntax is excluded. Each candidate is bound to the case, input revision and final
presented decision. The limits are 12 candidates, 2048 characters per item and at
most 3 ordered selections. Total/offered/omitted counts are explicit.

The model may return `verificationPlan: { selectedIds: [...] }` beside the exact
decision reference. No free-form factual rationale or numbers are accepted.
An absent plan stays absent. An empty selection is shown honestly.

The host checks closed shape, uniqueness, membership and binding. This validates
only selection of current supplied checks, not their priority quality. A rejected
advisory plan cannot replace the actual decision or required checks. An invalid
base proposal retains its previous failure/hold. Local runners cannot forge the
private model-origin marker.

The optional envelope record stores selected host text and binding hashes.
SQLite reload reconstructs the current candidates and rejects changed text or
binding. Old envelopes remain valid. The current private research view displays
the plan after mandatory safety action/reasons. Commercial or unguided historical
views omit it. Repeated held text links to the numbered reason; all mandatory
checks remain available.
