# 평가 계획: 추천의 유용성과 차단의 정확성

이 문서의 목표치와 통과선은 계획이다. 개발 실행은 [1차 기록](evaluation-development-run.md)과 [재평가](evaluation-legal-refresh-20261114.md)에 있으며 독립 정답 기반 성능과 구별한다. 2026-11-15부터 [추천 목표](recommendation-goal.md)를 기준으로 평가한다. 반출이나 계약 승인은 정답 조건이 아니다.

## 대상과 평가 단위

사용자는 중소 제조업체 환경 담당자다. 사진과 설명, 발생 공정, 수지, 오염, 질량, 지역, 기준일, 후보 경로, 근거 버전을 한 사례로 연결한다. 사진만으로 화학성분, 유해성, 법적 코드를 확정하지 않는다. 누락은 그대로 보관하고 정답에 맞춰 채우지 않는다.

현장 자료는 받지 못하므로 공개 자료와 합성 사례로 구성한다(#42). 공개 출처, 합성 가정, 실제 확인 사실을 구분한다. 공개 자료 기반 계산은 시나리오 추정이며 실제 견적이나 실측 감축이 아니다.

같은 사진, 사업장, lot의 변형은 같은 그룹으로 묶어 개발18/잠금12로 나눈다. 잠금 사례와 정답은 최종 평가 전 튜닝에 쓰지 않는다. 이미 공개된 사례는 새 라벨을 붙여도 미노출로 돌아가지 않는다. 부족분과 노출 이력은 [인벤토리](evaluation-inventory.md)를 따른다.

수집자를 제외한 두 사람이 모델 출력과 다른 사람 초안을 보기 전에 각각 라벨을 고정하고 팀장 또는 멘토가 불일치를 조정한다. 법적 코드 미확정만으로 보류를 정답으로 두지 않는다. 추천 경로 1~3순위와 동률, 근거, 막아야 할 위험, 추천을 바꿀 핵심 정보, 실행 전 확인 목록, 확신도와 범위를 적는다. 필수 근거를 검증할 수 없어 추천하지 못하면 해당 근거와 사유를 명시한다. 전문가 검토 여부와 검토자의 자격 및 노출 이력을 기록한다.

추천 산출률과 차단 정확도를 함께 보고한다. 보류율만으로 성공을 주장하지 않는다. 분모 0은 100%가 아니라 N/A와 사유다. 개발18/잠금12, 공개/합성, 수치 계산 가능/불가를 분리하고 11/12처럼 원시 건수와 층별 실패를 보고한다. 근거 존재와 근거 지지는 별도로 채점한다.

독립 사람 라벨 전에는 compared 비율, 실행 오류, 목록 표시 유무 같은 관측만 보고한다. 차단 정답, 순위 일치, 근거 지지를 모델 자체 판단으로 채점하지 않는다. 허가 유효성, 인수와 계약, 실견적과 실측, 계수 현장 적용 검토, 현장 승인은 추천 선행 정답 조건이 아니다. 권리, 단위, 경계가 검증되지 않은 값은 계산 근거로 쓰지 않는다.

## 기준선과 개선 실험

같은 개발 사례로 A(일반 LLM), B(출처 검색 포함), C(구조화 도구와 추천 및 안전 차단)를 비교한다. 모델, 입력, 출처, 가능한 샘플링 설정과 평가 기준을 고정하고 각 팔의 프롬프트와 도구 차이를 공개한다. 추론 비결정성을 기록하고 실패를 숨기는 재시도는 금지한다. 과거 C 보류 게이트 실행과 compared 0/18은 당시 버전의 사실로 보존한다.

실행 기록은 runId, caseId, corpusVersion, gitSha, modelDeployment, promptVersion, sourceSnapshotIds, startedAt, latencyMs, tokenUsage, outcome, citationAudit, reviewer, errorCategory를 포함한다. 원본 로그와 실패를 분모에서 지우지 않고 비밀값과 개인정보를 제외한다.

개선 기록: 문제 관찰 → 사례 ID → 원인 가설 → 한 가지 변경 → 같은 개발 사례 재평가 → 개발18건의 추천 산출과 차단 영향 → 남은 한계.

최종 평가는 모델, 프롬프트, 도구, 규칙, 출처, 코드 SHA, 코퍼스를 동결한 뒤 미열람 잠금12건을 최초 실행하고 원시 건수와 버전을 보존한다. 잠금 결과 확인 후 동작을 바꾸면 같은 12건 재실행은 회귀 확인이다. 새 독립 성능은 새 미열람 사례로만 주장하며 시간상 확보하지 못하면 미검증으로 표시한다. 모델 결과로 사람 라벨을 대신하지 않는다.

## 구현 팀의 실물 QA

1. 공개 사진과 명시한 합성 공정의 정상 사례를 실제 앱에서 입력하여 경로 비교, 추천 이유, 업체 후보, 계산 가능 항목, 실행 전 확인 목록까지 완주한다. compared를 실행 허가로 표시하지 않는다.
2. 같은 사진에 유해 접촉 또는 모순 입력을 넣어 차단 이유를 확인한다. 허가나 실견적만 빠진 정상 사례는 경로 비교 전체를 막지 않는지 별도로 확인한다.
3. 출처 없는 인용과 단위가 틀린 값은 채택하지 않고, 해당 항목의 미확인과 가능한 대안 비교를 구분한다.
4. 기본 구독 runner 또는 선택한 Azure 실패는 실제 실패로 표시한다. 백업 녹화는 live로 표시하지 않는다.
5. 각 시나리오의 입력 JSON, 정확한 명령 또는 페이지 동작, 출력 JSON과 화면, 출처 버전과 SHA를 함께 보존한다. CI 통과만으로 추천 품질이나 실제 제공자 연결을 입증하지 않는다.
