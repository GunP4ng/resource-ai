# 100점 심사 기준을 증거로 연결하기

공식 근거: AXR OT PDF p.5, https://axr.kr/dashboard/notices/9/files/32 (2026-11-05 확인).
배점은 공식 값이고 아래 목표·전략은 팀의 설계 제안이다. 설계만으로 점수나 수상을 보장하지 않는다.

**2026-11-15 갱신:** 제품은 경로 비교·추천으로 판단을 돕는다. [추천 목표](recommendation-goal.md)에 따라 3분은 공개·합성 사례의 비교·추천, 2분은 유해 의심/입력 모순 차단과 실행 전 확인 목록을 보여준다. 허가·인수·실견적·실측·계수 적용·현장 승인 미확인만으로 전체 비교를 보류하지 않는다. 과거 실행 영상은 당시 버전으로 표시하며 새 추천 동작의 증거로 재사용하지 않는다.

|---|---|---|---|

## 15분 발표안

0–2분: 누구의 어떤 문제인지, 한 사례의 현재 처리 과정과 손실.
2–4분: 공개데이터 연결과 작은 MVP 범위, 대안 구조 비교 후 선택 이유.
4–7분: 공개·합성 사례의 비교·추천 E2E 데모. 경로 장단점·순위 이유·출처·업체 후보·계산값 라벨·실행 전 확인 목록과 선택한 provider의 실제 요청 추적을 보여준다. 비밀값은 가린다.
7–9분: 유해 의심 또는 입력 모순으로 차단한 이유를 보여준다. 현장 허가/견적만 빠진 정상 입력은 비교가 유지되는 차이와 실행 전 확인 목록을 함께 보여준다.
9–12분: 기준선→근거 검색→판정 게이트의 측정 결과와 실패 사례.
12–14분: 현장 적용 조건, 비용/탄소 가정, 제한과 확장 순서.
14–15분: 결론과 역할. 질의 7분 별도.

현재 기본 실행은 구독 계정이며 Azure는 명시적으로 선택하는 경로다. 선택한 제공자의 실제 실행은 요청 추적 ID·사용량·권한과 실패 처리로 증명한다. 로컬 데모는 외부 모델 호출이 없음을 표시하고 제공자 실행 증거로 사용하지 않는다. 수업에 나온 GPU VM·VectorDB·GraphDB를 모두 넣는 것은 목표가 아니다.

## 예상 질의

- “사진으로 폐기물 코드를 어떻게 확정하나?” → 확정하지 않는다. 발생원·성상과 검증된 근거를 바탕으로 후보 경로를 비교하고, 유해 의심·금지·검증 실패 인용·모순은 차단한다. 코드 미확정만으로 가능한 경로 비교 전체를 멈추지 않는다.
- “이 업체가 정말 받아 주나?” → 공개 허가/지역 조건으로 추린 후보이며 계약·인수 가능 여부는 최신 확인 단계다.
- “탄소가 얼마나 줄었나?” → 실측 감축이 아니라 명시된 기능단위·경계·계수의 시나리오 추정이다. 대체율 등 민감도와 불확실성을 제시한다.
- “왜 senpi인가?” → 검증된 도구 확장·세션 재현을 이용하되 도메인 판단은 독립 모듈로 분리한다. 최종 구조 선택은 ADR 참고.
- “근거가 오래되면?” → 조회 시점과 유효 기간을 기록한다. 검증 실패 인용은 사용하지 않고 필수 근거를 재확인한다. 업체 허가 유효성 미확인은 후보 라벨과 실행 전 확인 목록으로 구별한다.
- “평가 30건으로 일반화 가능한가?” → 제한된 MVP 검증이다. 표본별 실패·보류·미검증 범위를 공개한다.
