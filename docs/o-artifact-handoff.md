# O4 자료 설치·재평가 인계

**2026-11-15 공개 사진 후속 인계:** [공개 사진 개발 묶음](../data/o-public-images/2026-11-15/README.md)에 CC0 선언을 대조하고 식별 내용을 제외한 실제 PNG 3장, 출처·권리 발췌와 raw/canonical 해시, 별도 합성 `PUBLIC-IMG-DEV-001` 입력·lineage·artifact를 추가했다. H006과 같은 출처인 1장을 포함하며, 독립 현장 사례·사람 라벨·미노출 holdout 추가는 각각0이다. J는 근거·미상·계산 불가를 검토하고, H의 실제 provider/model/purpose 승인·실행 ticket은 별도 인수한다.

비공개 QA에서는 실제 저장 전용 업로드3건의 수신·미리보기 해시를 실제 actor/case/input revision에 연결하고 기존 CLI check→install→인증된 명시적 재평가를 완료했다. 설치만으로는 보고서가 바뀌지 않았고, 재평가 뒤 정확한 artifact hash와 합성·현장 근거 아님·검토 보류·모델 호출 없음이 표시됐다. 잘못된 revision·비인증 미리보기·모델 동의 요청을 거절하고 기존 결과를 보존했으며 저장 철회 후 미리보기도 차단했다. 데스크톱/모바일, 밝고 어두운 화면을 확인했다. 일반 clone의808tests/0fail, 타입 검사·두 빌드·scaffold smoke가 통과했다. 실제 사진 추론·현장·provider 인수는 완료하지 않았다. 재현 절차와 최종 검토 상태는 묶음 README와 qa.json을 따른다. 아래 PR58과 2026-11-07/12 수치는 각 당시 범위다.

**2026-11-15 PR58 최초 가격 패키지 인계:** [공개 출처·개발 패키지](data-sources-public.md)를 참조한다. 새 반입은 KECO 참고가격 2레코드와 사진 없는 합성 `PUBLIC-DEV-001` package 1개다. 이번에 추가·검증한 독립 현장 사례·사람 라벨·미노출 holdout·모델 입력 사진은 각각 0이다. 미열람 원본 전체에 그런 자료가 없다는 뜻은 아니다. 기존 H10의 공개 라이선스 기록은 운영·모델 동의와 별개이고, raw700의 권리·진위와 승인 공유 위치는 미확보다. 데이터셋·파생본·썸네일을 독립 사례로 합산하지 않는다. J의 현행성·사례 적용 보류와 비용·탄소 계산 불가를 유지한다. 실제 현장·평가 인수와 #42 provider 승인 자료는 별도 인계가 필요하다.

비공개 합성 QA 계정·사례를 준비해 기존 `o-artifact.ts check`의 정확한 actor·case·input revision·artifact hash 통과와 비설치를 확인했다. 잘못된 revision·손상 파일·비활성 계정·다른 소유자·없는 state는 모두 거절됐고 기존 상태도 보존됐다. 전체 타입검사는 통과했다. 일반 clone에서는 797 tests / 0 failures와 두 빌드·smoke가 통과했다. 명명된 worktree에서는 기존 평가 helper의 Git 공용 참조 처리 결함으로 4개가 실패했으며, 해당 평가 코드·테스트는 변경하지 않았다. 마지막 출처 정정 후 관련 7개 검사도 통과했다. 실제 범위·해시·최종 검토 상태는 [qa.json](../data/o-public-development/2026-11-15/qa.json)에 기록한다. 이 계정은 QA용이며 운영 현장 연결이나 설치·재평가 완료의 증거가 아니다. 아래 2026-11-07/12 결과는 역사적 기록이다.

## 구현 내용

- 활성 username에서 내부 actor ID를 조회하고 소유 사례, 입력 revision,
  30분 편집 기한을 확인한다. 존재하지 않는 state/database를 새로 만들지 않는다.
- `check`는 기존 검증기로 자료와 설치 대상을 확인하고 자료를 게시하지 않는다.
- `install`은 `{ record, sha256 }` 원본 bytes를 private actor/case/revision 경로에
  설치한다. 같은 bytes는 재시도 가능하고 다른 파일 덮어쓰기는 거부한다.
- 파일 크기, 소유자, 접근 권한, 심볼릭 링크, 단일 링크, 파일 변경을 검사한다.
  파일과 디렉터리 동기화가 성공해야 성공 결과를 반환한다.
- 중단된 설치가 남긴 디렉터리를 재사용할 때도 각 상위 디렉터리를 동기화한다.
  이 누락은 검토에서 발견해 실패 회귀를 먼저 확인한 뒤 수정했다.
- CLI를 app 빌드에 포함해 저장소 밖 작업 디렉터리에서도 실행할 수 있게 했다.
- 설치는 모델 호출이나 사례 재평가를 실행하지 않는다. 기존 인증된
  `/cases/:id/answers`와 `baseVersion`으로 명시적으로 재평가해야 결과에 반영된다.
- 공통 DTO, H/J 판정·실행 계약, 계산식, UI 렌더링과 사진 권한은 변경하지 않았다.

명령, JSON 출력, private 경로 준비 및 중단 복구 절차는
[운영 인계 문서](o-runtime-integration.md#http-recovery-and-exact-artifact-installation)에 있다.

Linux/Bun 1.4.2 기준이다.

| 최종 전체 `bun test --timeout 30000 ./tests` | 549 pass / 0 fail, 24개 파일 |
| source/Node/Bun 테스트 strict 검사 및 O 테스트 타입검사 | 통과 |
| extension 빌드 및 packaged app/account/artifact 빌드 | 통과 |
| 공식 offline smoke 및 `git diff --check` | 통과 |
| 상위 디렉터리 동기화 회귀 | 수정 전 6 fail, 수정 후 6 pass |
| 실제 CLI·HTTP·Chrome native 폼 | 로그인→사례 생성→정확 입력 export→자료 설치→명시적 재평가 확인 |
| 설치 직후 보고서 | 기존 결과 유지, 설치 hash가 평가 결과로 자동 반영되지 않음 |
| 명시적 재평가 후 | 버전 2, 정확한 artifact hash, 합성 표시, 현행성 보류 유지 |
| 잘못된 expected revision | exit 1, 성공 stdout 없음 |
| Astra 최종 재검토 | 로컬 변경 APPROVE |

CLI 테스트는 실제 private filesystem과 SQLite를 사용한다. 실패 회귀는 테스트
프로세스에서 선택한 `fsync`만 실패시킨다. 실제 전원 장애 실험을 수행한 것은 아니다.
스크린샷은 CDP timeout으로 미확보했으며 실제 동작과 접근성 트리만 확인했다.
합성 계정·입력으로 로컬 runner를 사용했고 실제 외부 모델 호출은 하지 않았다.
