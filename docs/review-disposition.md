# 독립 검토와 반영 기록

2026-11-05 별도 새 맥락의 리뷰어가 사용자 브리프·문서·설치 패키지 API·골격을 심사위원 관점에서 검토했다.

**최초 판정: REQUEST CHANGES. 잠정 설계 인계 준비도 80/100.**
문제해결력 17, 현장적용성 15, 창의성 16, 전달력 17, 판단 신뢰성 15였다.
이는 실제 대회 점수·예상 수상 점수·제품 성능이 아니며 수정 후 점수를 임의로 올리지 않았다.

## 차단 사항과 수정

| ID | 리뷰어 지적 | 반영 | 리드 재검증 |
|---|---|---|---|
| B1 | 계산 입력에 기준선·견적·활동량·계수 참조가 없고 출력이 단일 배출량뿐 | `ComparisonInput`, 단위별 `QuoteBasis`, `ActivityInput`, 버전 고정 `FactorRecord`, 항목별 비용/탄소와 총배출/크레딧/순배출, `no-baseline` 추가 | 같은 case에 quote A/B를 연결하는 타입 예시와 기준선 없는 출력을 확인. 타입체크·빌드·기존 실제 loader/SDK smoke 종료 0 |
| B2 | 개발 노트의 “잠금셋 영향”이 평가 격리 정책과 충돌 | 개발 18건 기록과 동결 후 최초 잠금 12건 기록 분리. 평가 후 동작 변경은 기존 사례의 회귀 확인이며 새 독립 평가는 미열람 사례 필요 | 평가 문서와 11/16–21 일정 교차 읽기, 버전별 결과 표기 확인 |

B1은 계산기 구현을 추가한 것이 아니라 팀의 공유 입력/출력 계약을 보완한 것이다. `comparison.examples.ts`의 null은 실제 자료 미확보를 뜻한다. 런타임 파서·단위/권리 검증·산술·보고서 구현은 R03–R09에서 팀원이 수행한다.

## 비차단 메모 반영

- 수지 후보 일치율과 폐기물 코드 후보 일치율을 분리했다.
- 11/6에 수지·지역과 법령/업체/가격/계수별 가능·보류 상태를 결정하도록 R02를 구체화했다.
- 현장 인터뷰 섭외 담당/기한과 확보 실패 시 내부 역할극 표기 정책을 추가했다.
- R08의 host 게이트에 빈 근거·미존재 source ID·권리 미확인 자료 배포 사용을 거부하도록 명시했다.
- 발표 데모는 정상 3분+보류 2분, 총 5분으로 통일했다.

## 최종 상태의 해석

리드가 두 차단 사항의 수용 조건과 실제 재검증 결과를 대조하여 **반영 완료**로 처리했다. 독립 리뷰어의 수정 후 재승인 또는 새로운 점수는 받지 않았다. 최초 검토 결과와 리드의 수정 확인을 구분한다.

새 ulw-plan에 대한 계획 심사 게이트가 아니라, 이번 브리프가 요구한 독립 설계 검토 1회를 수행한 기록이다. 제품 미구현·Azure 미호출은 리뷰어도 이번 골격 범위의 반려 사유로 삼지 않았다.
