# 질량 선택 질문과 한 번의 답변으로 이어지는 추천

## 사용자 흐름

질량만 모르는 경우에도 다른 필수 사실과 공개 근거가 있으면 정성적 경로를 추천한다. 비용·탄소는 계산하지 않고 이유를 설명하며, 사례 화면에 **“질량을 입력하면 비용·탄소를 계산해요” (선택)**를 표시한다.

질량을 답하면 같은 사례의 버전이 올라간다. 해당 사례에 검증된 견적·계수·계산 경계 등 자료가 있으면 기존 계산기가 값을 갱신한다. 질량만으로 견적이나 계수를 만들어내지는 않는다. 자료가 없는 기본 앱에서는 남은 부족 자료를 계속 표시한다.

회귀/브라우저 검증의 수치 예는 기존 **합성** 자료다. 질량을 모를 때는 추천+미산정, 같은 사례에2000kg을 답한 뒤에는240000KRW·45kgCO2e가 표시됐다. 실제 현장 견적이나 절감 성과가 아니다.

여러 사실이 빠진 경우에는 공정·수지·오염·접촉·지역 입력란을 같은 답변 폼 앞부분에 모았다. 선택 질량 때문에 다른 답변을 막지 않는다. `세척 완료, 잔류물 없음`처럼 완결된 명확한 표현은 `없음`과 동등하게 매칭한다. 불확실/유분 문장 안에 `없음`이 들어 있다는 이유로 깨끗하다고 처리하지 않는다.

## 바뀌지 않는 안전 경계

- 유해 접촉 또는 오염 이력이 미확인이면 질문한다.
- 혼합·다층·라벨 모순, 명시된 유해 접촉은 검토로 남는다.
- 수지/공정에 맞는 근거가 없으면 빈 추천을 발행하지 않는다.
- 수치 계산은 질량이 있어야 시작하며 기존 견적·업체·문서·계산 경계 검증을 유지한다.
- 실제 실행 승인과 현장 검토는 별개이며, 정성 추천의 낮은 확신도와 전제는 유지한다.

## 검사와 파생 자료

`disk app remains unsettled...` 테스트는 실제 transport와 terminal audit 진입을 기다린 뒤 주입한 시계로 **원래 요청의 기한**을 진행한다.200ms work budget이 transport 시점에 존재함을 확인한다. 작업 타이머가 닫힌 뒤 감사 처리는 원래 parent deadline을 공유한다. 외부 HTTP/요청 guard는30000ms circuit breaker이고 가상 시계는 즉시 이동하므로 실제 시간을 기다리지 않는다. 기존 상태 보존·미정산·감사 종료·consumed journal 검사는 유지한다.
