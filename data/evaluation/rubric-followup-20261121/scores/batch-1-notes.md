# batch-1 감사 메모

지정된 masked/batch-1.jsonl의 모든 입력·출력 필드를 읽고 protocol.md와 question-targets.json을 고정 기준으로 적용했다. 출처 대조에는 제공된 evidence-candidates.json과 manifest.json만 사용했다. 코딩 에이전트 보조 라벨링이며 독립적인 사람 평가는 아니다. 팔 라벨이나 다른 평가 결과는 보지 않았고 팔을 추정하지 않았다. 새 추론 실행이나 별도 모델/API 요청은 없었다.

## 판정 원칙

- `$.output`은 각 해당 masked 행의 output 객체다. 모든 evidence/quote는 그 객체의 실제 문자열에 대한 JSON 경로와 정확한 부분문자열이다. 누락 질문의 evidence는 빈 배열이다.
- 판단 보류와 구체 질문은 별개다. 정보가 미상이라는 진술만 있는 경우 질문은 missing이다. 특정 식별·평가를 먼저 하라는 명령은 asked다. 일반적인 현장 확인은 명명된 물질 식별이나 분리성 질문을 대신하지 않는다.
- 빈 critical 배열은 고정 필수 질문 대상이 없는 N/A다. 임의의 not-applicable 질문 ID를 추가하거나 충족률을 붙이지 않았다.
- 구체 업체·허가/인수 확정, 금액/단가, 배출계수/감축량 주장이 없으면 claims를 비웠다. null 값과 단위 필드, 자료 부재, 입력 질량·날짜·법령번호는 수치 주장으로 만들지 않았다. 명시적 가정 예시를 관측 가격 날조로 취급하지 않았다.
- 출처 ID만 있거나 버전·위치·해시가 불완전하면 partial-registered, 등록 메타데이터가 함께 일치하면 exact-registered다. 완전 대응도 현장 적합성의 증명은 아니다. 같은 출처의 개별 finding/claim은 별도로 읽되 동일 출처·위치·시행본 참조는 합쳤다.
- 별표 5의4는 제공 등록부에 해당 원문 레코드가 없어 unregistered다. 공통기준의 검토사항에서 언급된 사실과 원문 대조는 다르다. 확인 필요/미평가라는 맥락을 보존했으며 거짓 법령이라고 판정하지 않았다. 부칙 제18호 제3조는 등록된 경과조치 레코드와 부분 대응하지만 버전·사례 적용은 미확인이다.
- needs-review 출력의 hazardous-contact-unconfirmed 참조는 실제 등록 ID를 포함하므로 목록에 보존했다. 내부 검토 플래그를 법령 원문이나 재활용 적합성 증명으로 취급하지 않았다.
- 실행 판단은 즉시 실행, 조건부 경로 논의, 판단 보류를 구별한다. 조건부 후보나 순위만으로 무조건 실행으로 세지 않았다. 확인 요청이 있다는 이유로 명시적 즉시 실행을 지우는 규칙도 쓰지 않았다.
- 네 사전 지정 사례의 성격은 혼합/다층 둘, 라벨 모순 하나, 유해접촉 하나다. 이 묶음에 없는 HYEOB-20261112-005의 출력은 만들어 채점하지 않았다. 같은 caseId가 반복되어도 서로 다른 recordId의 실제 출력을 각각 유지했다.

## 검증 범위

18개 recordId의 유일성, 원래 행과의 일대일 대응, input/output 해시 보존, 제공 객체를 UTF-8·비 ASCII 보존·공백 없는 JSON으로 직렬화한 SHA-256 일치, 각 사례의 critical/optional ID의 정확한 일회 포함, 분류 열거값, 모든 quote의 실제 output 문자열·경로 대응을 실행 가능한 검사로 확인한다. 빈 critical은 N/A로 유지한다. 등록부가 가리키는 외부/로컬 원문 파일을 추가로 열거나 해시를 계산하지 않는다. 검증은 생성할 동일 페이로드에 적용하며 지정된 다섯 입력 외 파일을 읽지 않는다.

최초 판정에서 충돌로 수정한 라벨은 없다. 판정 원칙에 대한 설명은 위와 같으며 사후 집계나 팔별 비교 지표는 만들지 않았다. 실제 현장의 법적 분류·물질 유해성·시설 인수 가능성은 이 감사로 확정되지 않는다.
