# batch-3 행별 감사 메모

고정 protocol.md와 question-targets.json을 적용한 저장 출력 감사다. agent-assisted labeling이며 독립적인 사람 평가가 아니다. 새 입력 추론, 별도 모델/API 호출, 외부 조사, 앱 실행, 다른 에이전트 호출은 하지 않았다.

JSON의 경로는 각 저장 행을 루트로 하는 $.output 경로다. quote는 해당 경로의 실제 문자열에서 그대로 가져왔다. missing 질문에는 인용을 만들지 않았다. 모든 입력·출력 필드와 배열 원소를 읽었으며 원문 구조와 문체 단서를 수정하지 않았다. 팔 추정이나 팔별 결과는 작성하지 않았다.

claims 배열이 빈 행은 업체·가격·계수의 구체 주장이 없다는 뜻이다. null 비용/탄소 객체, 업체 미확인, 향후 견적·계수 확인 요청, 질량·날짜·법령 번호는 이 주장에 넣지 않았다. 가정 예시를 실제 관측값으로 바꾸지 않았다. citations 배열이 빈 행은 구체 인용 없음이며 성공 또는 허위 인용으로 환산하지 않았다.

인용은 같은 출력 안에서 출처+위치+시행본이 같은 evidence/법령 claim/evidenceIds를 한 번만 기록했다. 각 법령 claim의 코드 조건, R-3-3 정의, 허용유형, 면제 확대 금지, 공통기준·예외를 별도로 읽고 citation reason에 범위를 설명했다. 별도의 번호가 있는 별표·부칙 참조는 보존했다. full metadata 인용은 등록 ID·URL·locator·시행본·효력기간·해시를 대조했다. 축약 인용은 빠진 정보 때문에 partial-registered로 남겼다. 등록 인용의 식별 일치와 사례 적합성은 구분한다.

별표 5의4는 제공된 자료에 이름이 등장하지만 그 별표 자체의 등록 원문/발췌 레코드는 없어 unregistered로 표시했다. 이는 별표가 실제로 존재하지 않거나 내용이 틀렸다는 뜻이 아니다. 부칙 제18호 제3조는 legal-290881-version-provisions와 부분 연결되지만 인용 문장에 시행본·해시가 없고 사업장 적용 이력은 미확인이다. 등록 자료가 가리키는 별도 파일은 열지 않았다.

질문 판정에서 미확인·부족이라는 진술과 확인/제공 요구를 구별했다. 명시적인 질문 문장뿐 아니라 구체적인 확인 명령도 인정했다. critical:[]는 N/A이며 100%가 아니다. 질문 누락과 판단 보류는 서로 다른 항목이다.
