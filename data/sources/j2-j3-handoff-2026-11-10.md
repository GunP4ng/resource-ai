## 산출물과 입력/출력

`data/reference/legal/review-2026-11-10/`의 README와 JSON 파일들이 검토할 실물이다.

- 공식 입력: 현행 법령/고시 주소, 실제 연결된 버전 본문, 별표 PDF 4개, 제60호 개정문.
- 출력: 시각·응답 상태·SHA·locator, 발췌 대조, 다중 원문 지지 관계, 재현 CLI 입출력.
- 파생 fact는 네 원문 중 하나의 내용을 전체 사실로 복제하지 않고 F1~F4별 기여를 분리한다. 원본 ID·발췌 ID·새 파생 ID는 다르다.
- `verifiedThrough`는 자동 갱신하지 않았다. 실제 조회 결과와 운영 반영 여부를 분리한다. 11/10 CLI가 `currentness-unverified`를 반환하는 것은 새 증거를 아직 운영 레지스트리에 반영하지 않았기 때문이다.
- 고시 제8조의 “발급일부터 3년 이내”는 법령 스냅샷의 확인 기한이 아니라 해당 생산 확인서의 유효기간이다. 변경확인서 발급일로 자동 연장하지 않는다.

H/O 공통 계약, 병합된 #30 artifact installer와 #31 구독 회귀, 실제 현장 승인, 기존 dirty 재확인 코드 이식은 이 게시 변경에 포함하지 않았다. 별도 브랜치 커밋·push만 승인 범위이며 PR·이슈 변경은 수행하지 않는다. `evidenceIssue`의 다중 원문 제한은 `docs/o-handoff.md`의 “Separate J/H/O provenance integration limitation”에 기록된 기존 통합 제약으로 인계한다.

별표 4의3 발췌는 표를 텍스트로 재구성해 “재활용 유형:” 등의 설명 레이블을 더한 것이다. PDF의 연속 문장으로 검색하면 일치하지 않는다. 선행 03:46 UTC 대조에서 9쪽 화면의 행·열 대응을 확인했고 `pdf-comparison.json`에 문자열 불일치를 숨기지 않았다.

## 10건 후보·출처/권리·중복 그룹 인계 상태

**실제 후보 0/10건, 후보 manifest 미공급, 독립 라벨 미공급**이다. `qa-inputs.json`의 10개 조건 변형은 현장 후보 열 건이 아니며 평가 분모에 넣지 않는다. 같은 `j2-j3-reproduction` 입력 계열을 독립 사례로 부풀리지 않는다.

J/현장 제공자에게 각 후보의 비식별 caseId, 공개/합성/현장 구분, 수집자·수집일, 공정·수지·오염/유해접촉·평가일, 원본/파생 sourceId·locator·SHA, 사용/보관/배포 권리·철회/만료, 동일 발생원/문서/사진/조건 변형을 묶는 duplicateGroupId를 요청한다. 아직 받은 자료가 없어 값이나 열 개 빈 후보 레코드를 만들지 않았다. 질량·견적·허가/인수·계수는 별도 증빙 전 unavailable이다.

수집자가 아닌 두 검토자의 독립 라벨과 불일치 조정·개발18/잠금12 그룹 분리는 팀장에게 인계한다. 잠금 정답은 개발자 튜닝용으로 공개하지 않는다. 사례 적용과 권리 확인은 선택 법령의 현행 링크 확인과 서로 다른 축이다.
